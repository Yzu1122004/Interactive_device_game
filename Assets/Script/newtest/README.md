# prototype：手推輪椅、Arduino 與語音控制

新程式放在 `Assets/Script/newtest`，場景為 `Assets/Scenes/prototype.unity`。舊 Player／Port 程式、共用輪椅 Prefab 與其他場景不需更動。

## 語音操作分工

保留 `PrototypeInput > Prototype Voice Control > Use Route Navigation` 開啟，使用統一的自由移動與目的地導航。按住 V 錄音、放開辨識；錄音時先暫停，新的有效口令決定下一個動作。短口令直接執行，其他句子交給 Groq LLM 判讀；無法確定意圖或辨識失敗會保持暫停。

| 口令 | 行為 |
| --- | --- |
| 直走／前進 | 以目前朝向自由前進，持續到停止口令、空白鍵或碰撞 |
| 後退 | 保持面向自由後退，持續到停止口令、空白鍵或碰撞 |
| 左轉／右轉 | 立即轉約 45°；正在自由移動則低速邊走邊轉，完成後維持原本前進／後退；停著則原地轉完停住 |
| 前進一點／後退一點 | 低速微調約 30 公分後停住，不會恢復先前的移動 |
| 左轉一點／右轉一點 | 原地微調約 15° 後停住 |
| 回頭／掉頭／迴轉 | 原地旋轉約 180°；先前正在自由移動則完成後繼續原本的前後移動，先前停著則停住 |
| 停下來／停止 | 煞車、取消當前語音動作 |
| 門檻／過門檻／幫我跨過前面的門檻 | 在前方近距離檢查指定門檻，模擬協助抬前輪、前移、抬後輪越過，最後停住 |
| 去路口／去前面的路口／去下一個路口 | 依朝向選擇前方可到達且沿線距離最近的路口，沿路網前往並停止 |
| 去路口一／去路口1 | 指定名稱導航，不受目前朝向限制 |
| 去王阿姨家／前往王阿姨家／王阿姨家 | 沿路網前往目的地，到達後停住 |

自由口令不需在藍線附近，也不需路網。導航途中說自由口令會取消原導航；導航途中說左轉／右轉會立即轉向並以前進方式繼續自由移動，不再等下一個路口。重新說「去某處」才會規劃路徑。說「直走／前進」會取消未完成的轉向，改沿目前朝向前進。

自動控制期間手推與 WASD 不會中斷語音動作。先按空白鍵煞車、取消自動移動，再用手推／WASD 接手；按住 V 錄音及等待辨識期間會維持原動作，也不會直接切成手動。語音「停下來」、碰撞、到達目的地與微調完成仍會停止；離開 Game 視窗會取消動作並煞車。

「一點／一點點」是微調指令的一部分，會保留辨識；「前進一下」視為一般持續前進。否定與順序會交由語意模型處理；任意指定秒數／距離／速度／角度、多動作序列與未支援條件監看，會要求重新說明，不會省略限制自行移動。

「前面的路口」以輪椅朝向為準，前方左右各 `Front Junction Half Angle = 60` 度為候選範圍。略過已抵達的路口及不連通節點，以實際路網最短距離排序；找不到時提示「前方沒有可到達的路口」，不選身後路口。名稱以「路口」開頭，或有至少三個連接方向的節點，會視為路口。若要選身後或特定位置，仍可說明確名稱。

## 自然語句理解

輪椅使用獨立的「Whisper STT → 意圖判讀 → 動作驗證 → 輪椅控制」流程，不依賴或修改 AI 老師尚未完成的語意模組。保留 `Use Route Navigation` 與 `Enable Semantic Understanding` 開啟；預設 `Intent Model = openai/gpt-oss-20b`（Groq 供應，不需要另設 OpenAI Key）。GPT-OSS 使用 `reasoning_effort=low`、`include_reasoning=false`，completion 上限 1024 tokens，動作只讀最終 JSON；其他自訂模型不會帶入 GPT-OSS 專用參數。短口令不必多等一次模型請求，其他說法使用相同 Groq Key 向 Chat Completions API 判讀，送出完整轉錄文字、目前移動狀態及場景地點名稱。

語意理解不限定三個句型，會依整句判讀行動、否定及到路口後才執行等關係。例如「這裡先待著，不要繼續往前」「能不能幫我往後挪一小步」「前面路口到了再往右邊繼續走」可分別表達停止、微退、到路口右轉。這些為意圖範例，不保證模型對每次說法都判讀正確；畫面同時顯示辨識文字與理解動作，可對照試跑結果。

模型只能輸出程式支援的行動與地點，不輸出馬達參數或程式碼。結果格式、動作、方向、地點與模型信心會檢查；不確定、回覆不完整、HTTP 錯誤或逾時不會套用新動作，原本的移動繼續；原先停著則維持停止。未知地點不會執行該導航要求。不明確時畫面提出問題，下一次按住 V 重新說完整要求；目前不是保留多輪對話的助理。

「到前面路口右轉／左轉」會先沿路網抵達路口，再按來向選對應的實際路段繼續沿線。沒有指定方向的分支則停住提示；後續優先直行，唯一延續路段可沿彎道繼續，遇到需要另作選擇的路口或盡頭就停止。空白鍵、新的自由移動、微調、停止與碰撞都會取消原本排定的轉向。

空白鍵可取消 STT 與 LLM 等待，舊回覆不會重新啟動移動。語音停止需要辨識與可能的語意請求時間，立即煞車使用空白鍵。LLM 連線失敗時不會用片段關鍵字猜測長句；已知短口令仍能直接執行（仍需 STT 連線）。目前不支援任意多步任務、定時等待、自訂數值或視覺條件判斷。

## 編輯隱形路線與地點

目前場景保留你擺放的「起點、路口1、王阿姨家」。目的地的 `Destination Name` 已是「王阿姨家」。

- Scene 視窗開啟 Gizmos 可看藍色連線及節點標籤；遊戲畫面不顯示這些輔助線。
- 拖動空物件可調整節點位置；彎道、繞障應增加中繼點，避免直線穿過障礙物。
- 按住 Ctrl 選取兩個節點，可在 Inspector 連接／解除連線，也可使用 `Prototype > Routes` 選單。
- `Connections` 拖入另一個節點即可雙向連線；新增節點掛上 `PrototypeRouteNode`，並放在同一個 `RouteNetwork` 下面。
- 普通節點用物件名稱導航，例如「去路口1」；`路口一` 也可。目的地另外填 `Destination Name`，例如「王阿姨家」。重複名稱會提示指定，建議每個地點使用不同名稱。
- `RouteNetwork > Start Node` 指定起點。導航接入最近路段，離線超過 `Max Attach Distance = 2` 公尺時拒絕導航；可先用自由移動或手動回到附近。

## 協助跨門檻

場景中既有的「門檻」已連接到 `PrototypeInput > Prototype Threshold Crossing > Threshold`；沒有新增另一個障礙，也未修改門檻的外觀、位置或 Collider。輪椅的 `Prototype Route Navigator > Threshold Assist` 指向這個協助元件。

說「門檻」「幫我過門檻」即可開始完整動作；其他長句由 LLM 判斷 `cross_threshold` 意圖。「不要過門檻」不會觸發短口令。動作順序：靠近 → 前輪抬起 → 前輪前移越過 → 協助後輪抬起 → 後輪前移越過 → 平穩落下並停住。

請先靠近、面向門檻並保持接地。預設偵測範圍 1.5 公尺、門檻相對地面的高度上限 0.4 公尺、行進方向厚度上限 1.2 公尺、抬起角度上限 30°，協助速度 0.25 公尺／秒，最多 30 秒。超出範圍或幾何不適合時會拒絕並顯示原因。高度與厚度依實際 Collider 世界範圍計算，與 Inspector 的單一 Scale 值不相等；若門檻看起來低但無法執行，請先檢查 Collider 的 Size 和旋轉。

這是遊戲中的虛擬協助者：以外力與扭力追蹤分階段的支撐姿態；不直接寫入 Rigidbody 位置／角度／速度，不停用重力、碰撞或 WheelCollider。抬輪時可能暫時離地，因此只有此協助狀態使用自己的尺寸、抬輪間距與逾時檢查；一般移動仍保留原離地停止保護。實際輪子姿態確認抬起間距後才進下一步，懸吊伸長造成間距不足時會施加有限額外支撐，仍無法跨越就停止。

協助時驅動輪鬆開煞車並停止馬達，由虛擬協助外力推動。指定門檻的碰撞由物理解算保留；遇到其他前方障礙會取消。按住 V 錄音與等待辨識時繼續跨越，空白鍵或「停止」取消後恢復一般物理與煞車；中途取消不會瞬移回原位置。這是雛型呈現，實際抬輪效果需要在 Unity 場景調整，不能作為真實輪椅跨越操作指引。

## 移動參數與碰撞

輪椅上的 `Prototype Route Navigator`：自由速度 `Free Move Speed = 1` 公尺／秒、一般轉角 `Free Turn Angle = 45` 度、轉向速度上限 `Free Turn Speed = 45` 度／秒，邊走邊轉速度上限 `Free Turn Move Speed = 0.35` 公尺／秒；轉向卡住超過 `Free Turn Timeout = 12` 秒會停止。這些為物理控制目標，實際速度與角度受接觸、地形及煞車影響。

微調參數：`Nudge Distance = 0.3` 公尺、`Nudge Angle = 15` 度、`Nudge Move Speed = 0.35` 公尺／秒、`Nudge Rotation Speed = 35` 度／秒，卡住最多 `Nudge Timeout = 8` 秒停止。撞到東西後可先「後退一點」，再「左轉一點／右轉一點」調整，接著自由移動或重新說「去王阿姨家」。

導航速度 `Move Speed = 2.5` 公尺／秒，轉向目標上限 `Rotation Speed = 100` 度／秒。進入 `Arrival Tolerance = 0.5` 公尺的抵達範圍，或在線附近越過節點時，先煞車記住抵達，再進入下一段路，避免滑過節點後掉頭追點。

自由移動、微調及導航都透過 WheelCollider 馬達，不直接寫入 Rigidbody 位置、角度或速度。Rigidbody 保持重力、碰撞開啟、Is Kinematic 關閉。前後速度以兩驅動輪平均 RPM 回授；轉向以車身實際角速度回授，`Route Yaw Speed Gain = 40`、`Route Turn Torque Limit = 65`，扭力平滑增加。

接地會檢查所有輪子；輪子回報未接地時，補充向下的地面探測，忽略自己、Trigger 與陡直表面。短暫接地中斷不反覆煞車，真正離地超過 1 秒停止自動控制，重力仍作用。前進撞到前方實體障礙會停止；微調後退可退開既有前方接觸。原地微轉保留接觸物理解算，卡住則逾時停止。目前沒有自動繞障。

Editor 中的 `Record Diagnostics In Editor` 預設記錄 `Logs/prototype-route-physics.csv`，包含自由移動／轉向／微調／導航階段、位置、接地、RPM、扭力、煞車等；最多約 90 秒，不包含金鑰、錄音或辨識文字，建置後停用。

## 展示步驟

1. Arduino 沿用 `Assets/Arduino/FINAL/FINAL.ino`，通訊速率 **9600 baud**。
2. 關閉 Arduino IDE 的序列埠監控視窗，避免占用 COM 埠。
3. 開啟 `prototype`，選取 `PrototypeInput`，將連線元件的 `Port` 設為實際埠號（目前沿用 **COM4**）。
4. 按 Play，等待約兩秒讓 Arduino 啟動；連線元件的 `Runtime Status` 可查看目前狀態。
5. 推動兩輪測試前後移動、單輪轉向與雙輪反向原地轉向。
6. 停推後輸入會於 0.12 秒到期，接著控制器平滑減速並施加待機煞車。

原場景校正值：`Invert Left Encoder` 開啟、`Invert Right Encoder` 關閉。如果某輪方向相反，調整對應選項。

保留鍵盤備用操作：W／S 前後、A／D 轉向、空白鍵煞車。取消輪椅控制器的 `Enable Keyboard Input` 可以關閉 WASD；空白鍵仍保留煞車。

## 語音展示

1. 在 `PrototypeInput > Prototype Voice Control` 的 `Api Key Override` 填入自己的 Groq API Key；也可以沿用 AI 老師的 `GROQ_API_KEY` 環境變數。新增環境變數後，重新啟動 Unity／Unity Hub 才會繼承設定。不要將真實 Key 提交到版本庫。
2. 接上麥克風。`Microphone Name` 留白會選第一個裝置；多裝置時可填指定裝置的完整名稱。
3. 按 Play，點選 Game 視窗，**按住 V 說話，放開 V 才送出辨識**。上方會顯示錄音、辨識結果與執行狀態。
4. 支援「前進／往前走」「後退」「左轉」「右轉」「回頭／掉頭」「停止」「去王阿姨家」，以及四個方向的「一點」微調。也接受「請幫我前進一下」這類簡單口語包裝。
5. 預設使用下表的自由移動與地點導航口令。若取消 `Use Route Navigation`，可回到舊的自由移動展示：前後移動 1 秒、轉向 1.2 秒，結束後煞車；此模式不支援目的地與掉頭。

每段預設最多錄音 10 秒（可在 Inspector 調到 15 秒），錄滿仍須放開 V 才送出。錄音過短、音量太低或無法判讀時不套用新指令，原本的動作繼續。按住 V 與等待網路辨識不會暫停移動；到達終點、碰撞或原動作完成仍按原流程停止。指令採完整比對，拒絕「不要前進」、連續多個動作及任意秒數／距離指令。

沿線自動移動與微調期間，手推或 WASD 不會取消語音移動；請先按空白鍵停止自動控制，再用手推／WASD。關閉 `Use Route Navigation` 的舊自由移動模式仍允許手動輸入取消語音動作。處於手動模式等待辨識時，若手推／WASD 接手，也會取消該筆辨識，避免較晚回傳的舊指令重新移動。空白鍵會取消錄音、辨識與語音動作。語音「停止」仍須等待網路辨識，立即煞車請使用空白鍵。離開 Game 視窗或切換應用程式會取消錄音／辨識並煞車。

這版沿用 AI 老師的 Unity 麥克風、WAV 與 Groq STT 流程；使用 `whisper-large-v3`、`language=zh`，不依賴老師角色、教材、情緒辨識或 TTS；LLM 意圖判讀使用輪椅自己的 `PrototypeVoiceIntent`。音訊只保留在記憶體並於放開 V 後上傳辨識，沒有另存錄音檔。服務參數見 [Groq Speech to Text 文件](https://console.groq.com/docs/speech-to-text)。

## 通訊與檢查

- Arduino 訊息格式為一行 `MOVE:左輪累積值,右輪累積值`，例如 `MOVE:-20,20`；並非單次位移值。
- 連線後發送原有的 `GAME_RESET`；第一筆有效計數作為基準，不產生移動。
- 非移動訊息（舊按鈕／技能訊息）會被忽略。
- 可從連線元件右上角選單執行 `Connect Arduino`、`Disconnect Arduino` 或 `Reset Arduino Counters`；拔插後用 Connect 重新連線。
- `Log Arduino Messages` 可顯示接收原文，預設關閉以免洗版。
- Unity 選單 `Prototype > Validate Input and Scene` 可檢查編碼器、語音指令、WAV 格式、路網連通性與場景引用；此檢查不會連接硬體或呼叫 API。

Groq 模型與 JSON mode 參考：[模型文件](https://console.groq.com/docs/model/openai/gpt-oss-20b)、[JSON 輸出](https://console.groq.com/docs/structured-outputs)。

2026-10-25 官方模型／免費額度列表仍包含 `whisper-large-v3`，維持語音辨識使用此模型；語意模型已由企業方案的 Llama 3.3 換為一般帳號可用的 GPT-OSS 20B。實際帳號權限仍需連線確認。參考：[可用模型](https://console.groq.com/docs/models)、[免費方案限制](https://console.groq.com/docs/rate-limits)。

2026-10-25 以目前專案設定的金鑰連線確認：模型清單包含 GPT-OSS 20B 與 Whisper Large V3；`whisper-large-v3` 的短靜音 WAV 請求回傳 HTTP 200（可存取，非辨識準確度測試）。GPT-OSS 20B 實際請求回傳 `model_permission_blocked_project`，需在 Groq 選取對應專案，至 [Settings → Projects → Limits](https://console.groq.com/settings/project/limits) 將 `openai/gpt-oss-20b` 納入允許模型／移出封鎖模型並儲存。這是帳號專案權限，不是金鑰失效；限制對該專案所有金鑰生效。參考：[模型權限說明](https://console.groq.com/docs/model-permissions)。

## 靠邊避讓

說「靠左一點／靠右一點」，或「前面有東西，靠右一點繼續走」。與「左轉一點／右轉一點」不同，靠邊依輪椅與障礙物的長寬及相對位置計算側前方路徑、恢復原朝向後繼續前進。導航中保留目的地，整台輪椅通過障礙物後再回到原路線。空白鍵隨時停止。

自由移動與導航允許實際碰撞，接觸障礙物後才停住，等待使用者選側或後退；微調與跨門檻保留各自流程。靠邊先檢查完整路徑的空間與地面支撐，途中繼續偵測障礙；空間不足不執行，可換側或先後退一點。偵測依場景 Collider，不會辨識沒有 Collider 的模型。沒有偵測到前方障礙時才使用預設 0.6 公尺偏移；有障礙時改以尺寸計算，較大的偏移會延長轉彎段。基本轉換長度 1.6 公尺、速度 0.3 公尺／秒，可在輪椅 Prototype Route Navigator 的 Side Bypass 調整。移動狀態會列出輪椅與障礙物的寬、長及計畫偏移量。單次前進段超過 6 公尺會停止規劃；這是局部避讓，不是全場景自動尋路。

預設不須手填尺寸：BoxCollider／MeshCollider 會依實際形狀範圍、旋轉及縮放換算；同一 Rigidbody 的障礙物會合併其子 Collider。靜態複合物件若沒有共同 Rigidbody，預設使用碰到的那個 Collider。

要手動提供尺寸時，停止 Play，在輪椅根物件或障礙物（可用共同父物件）加入 `Prototype Avoidance Footprint`，勾選 `Use Manual Size`，填 `Width`（本地 X 寬）、`Length`（本地 Z 長），必要時調 `Local Centre`。尺寸會套用該物件 Transform Scale；Scale 為 1 時一單位為一公尺。選取該物件可看到青色尺寸框。手動尺寸只控制避讓計算，不會修改實際 Collider；實際 Collider 仍會參與路徑空間檢查，因此尺寸也應與 Collider 對齊。
